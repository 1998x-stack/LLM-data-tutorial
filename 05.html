MODULE 05 / LLM DATA ENGINEERING

启发式规则过滤

从 C4 到 FineWeb：用真实论文证据理解过滤规则、阈值消融与误杀风险。

核心概念 · 工程实现 · 证据边界建议按图示顺序阅读
本章问题

当语料规模达到数十亿网页时，如何用便宜、可解释的规则清除明显噪声，同时避免把代码、列表、低资源语言和专业内容误删？

启发式规则的价值：便宜、透明、可审计

启发式过滤使用可计算的文档统计量和显式条件，例如文本长度、句子结构、行重复比例、URL 类别和占位符模式。它适合拦截明显异常数据，但不能单独定义“知识价值”。一条规则可以解释为什么删除了文档，却不能自动证明删除决策对目标模型有益。

C4：把“网页噪声”写成明确条件

T5 论文介绍的 C4 基于 2019 年 Common Crawl 数据构建。其公开描述包括：保留以终止标点结尾的行、丢弃过短页面和过短行、移除包含 lorem ipsum、花括号、特定不当词表或 JavaScript 提示的页面/行，并使用英语语言识别；此外还进行三句窗口级去重。

规则族目标噪声潜在误伤
句子终止标点菜单片段、断裂文本和无句子结构内容标题、列表、代码、某些语言的标点差异
最小句子数 / 行词数过短页面、稀疏片段短问答、定义、标题、简洁代码注释
占位符 / JS 提示模板占位文本、脚本提示页面技术文章在正文中讨论这些字符串
花括号部分代码、模板或结构化残留数学、代码教程、JSON 示例和技术文档
三句窗口去重跨页面重复片段与模板常见定义、法律声明和标准文本

重要的是：这些规则来自特定数据集和目标任务。它们不是“网页质量”的普适真理，也不应该未经审计就迁移到代码、论坛或多语言语料。

FineWeb：先做消融，再选规则

FineWeb 论文没有简单地把五十多条候选规则全部叠加。作者先在高、低质量数据子集上比较统计量分布，再提出候选阈值，随后通过数据消融评估其效果。论文的最终 FineWeb 管线处理了 96 个 Common Crawl 快照，形成 15T-token 数据集。

01

WARC + Trafilatura 抽取

从原始归档抽取网页正文，而不是直接把 WET 当作高质量主内容。

02

基础过滤

URL blocklist、fastText 英语得分阈值，以及来自 MassiveText 的质量与重复规则。

03

逐 crawl MinHash 去重

对每个快照独立去重，避免全局去重把旧快照中相对高质量的内容过度删掉。

04

选择性采用 C4 过滤

作者保留了部分 C4 规则，但没有采用终止标点规则，因为该规则在实验中移除了过多 token。

05

新增三条启发式规则

根据行标点、重复行字符比例和短行比例筛选低质量文档。

FineWeb §3.6 报告的三条自定义规则及其消融统计如下。这里的百分比是论文实验中被移除的 token 比例，不是任意数据集的默认参数：

统计量过滤条件该规则在消融中移除的 token
以标点结尾的行占比不高于 0.1210.14%
重复行字符占比不低于 0.1012.47%
短于 30 字符的行占比不低于 0.673.73%
如何正确解读：论文报告这三条规则联合使用时，在其 28B-token 消融实验中约移除了 22% token，aggregate score 提升约 1%。这是特定快照、模型规模、token 预算和评测集下的结果，不应被写成“所有语料过滤后必然提升 1%”。

把阈值变成可审计的实验

一个更稳妥的规则开发流程是：

  1. 定义目标语料和明确的负例类型，不要把“看起来不专业”当成标签。
  2. 从不同语言、来源、网页类型和文档长度分层抽样。
  3. 计算候选统计量，查看高质量与低质量样本的分布重叠。
  4. 提出候选阈值，人工检查边界样本和误杀样本。
  5. 做逐条与组合消融，记录过滤量、保留分布和下游影响。
  6. 将规则版本、阈值、统计口径、命中原因写入 filter_trace。

规则可以返回 keep、drop 或 review，不必每次都做二元删除。对不确定样本进入复核桶，通常比不断提高阈值更安全。

规则过滤与模型过滤是互补关系

规则擅长发现可明确表达的模式；模型分类器擅长从多个弱信号中估计更抽象的质量维度。两者都可能偏差：规则可能误删专业内容，分类器可能偏好与标注者相似的表达风格。DCLM 的研究表明，模型化过滤在其受控基准中很重要，但不能据此推断所有项目都应完全替换启发式规则。

工程上可以先用低成本规则排除明显异常，再对剩余样本做更昂贵的分类或人工抽检；也可以保留多个质量分数供后续采样，而不是一次性删除所有低分样本。
